# Roadmap

The single list of planned and in-progress work for `dsc`. Checked entries may be implemented on `main` but not yet released; released history lives in [CHANGELOG.md](../CHANGELOG.md). Unreleased completed work is described as "implemented on `main`", not "shipped".

Legend: [x] done, [~] in progress or partially done, [ ] not started. Stable roadmap codes (`R1`, `R2`, …) are never renumbered or reused.

## Shipped (highlights)

The built surface, grouped - see CHANGELOG for the full per-release detail.

- **Declarative sync** - `setting pull/push/diff`, `tag pull/push`/`rename`, `category pull/push`/`def` sync, `post`/`backup`/`emoji`/`topic` pull/push. Specs: [setting-sync](commands/setting-sync.md), [tag-sync](commands/tag-sync.md), [category-workflow](commands/category-workflow.md).
- **Theme management (complete)** - settings (incl. `pull/push`), fields (SCSS/HTML), assets (`set/unset`), enable/disable, attach/detach, palettes, `show`, remote `update`, API `install`/`delete`. Spec: [theme-management](commands/theme-management.md).
- **Compliance / cross-forum** - `sar` (GDPR SAR export), `setting audit` (one setting across the fleet). Spec: [subject-access-request](commands/subject-access-request.md).
- **Content** - `topic pull --full`, `topic title`/`tags`, `topic delete`/`restore`/`list --deleted`, `render` template substitution (incl. `--render` on push commands and code-fence protection), negative-ID user-list fix. Specs: [topic-pull-full-thread](commands/topic-pull-full-thread.md), [template-rendering](commands/template-rendering.md).
- **Ops / diagnostics** - `update` (skip-if-current, rootless Docker, parallel), `harden` (PQ-hybrid SSH), `file audit|push|pull` (checksum-verified SSH transfer, R53), `backup` (create/list/pull/push, setup-s3 with IAM rotation, fleet health), saved Data Explorer query inspection/execution with streamed CSV. Specs: [file-transfer](commands/file-transfer.md), [backup-s3-setup](commands/backup-s3-setup.md), [backup-health](commands/backup-health.md), [explorer](commands/explorer.md).
- **CLI / distribution** - universal `--format`, `completions install` (+ PowerShell), `man` pages, `version --format`, SIGPIPE-safe piping, config-path resolution, cargo-dist release + git-cliff changelog, `s/version++` one-command release, push/PR CI gate. Specs: [config-path-resolution](commands/config-path-resolution.md), [cli-design](cli-design.md).

## 1.0 launch checklist

Work toward `v1.0.0`. The stable `RXX` identifiers below are intentionally non-contiguous: completed items may be retained as checked entries or summarised above, but are never renumbered or reused.

**Decision, 2026-08-26: the Meta announcement is decoupled from `v1.0.0`.** `dsc` is announced as a pre-1.0, explicitly alpha tool. This is honest about where it is, sets expectations about breaking changes, and does not require the contract items below to land first. [compatibility](../docs/compatibility.md) already scopes the CLI contract to "takes effect with `v1.0.0`; pre-1.0 releases remain subject to change", so no documentation change is needed to announce at `0.x`.

## Planned

### Ops reliability

- [~] **R42 - `dsc update` failure detection and disk-guard recovery** - shipped: disk recovery (exact preflight measurement, safe dangling-image cleanup, re-measurement, shell-quoted manual guidance), SSH failures reporting exit status with bounded stdout/stderr context, and concise diagnosis in logs. **Stale since 2026-09-04:** the remaining item was reproducing two 2026-07-29 launcher invocations that returned non-zero after a successful update; the specific run context is unrecoverable now. Treat as closed unless the symptom recurs - if it does, capture `./launcher` exit codes and stderr in the same run as the update rather than reconstructing after the fact. Spec: [update-failure-detection](commands/update-failure-detection.md).
- [ ] **R54 - Agent-facing mutation controls** - adopt the useful safety patterns confirmed in CDCK's official `@discourse/mcp` 0.3.1 without duplicating its HTTP tool surface: a shared adaptive per-forum write governor that pauses all work for a host after a 429 and lowers concurrency; explicit command-family allowlists for a future `dsc job` rather than arbitrary shell or API execution; fresh-state preconditions and exact post-write verification for high-impact mutations where feasible; bounded, redacted diagnostics that distinguish an unavailable plugin/capability from a missing resource. Driver: agents and fleet jobs can amplify request bursts and mutation mistakes; the official MCP's opt-in writes, approximately one-write-per-second pacing, bounded output, and capability-specific errors demonstrate practical safeguards. Out of scope: an MCP server, dynamic remote-tool discovery, or HTTP transport in `dsc`.

### Content sync

- [~] **R49 - `dsc topic change-owner`** - Phase 1 implemented and verified against live ACCM 2026-08-25: `dsc topic change-owner <discourse> <topic_id> <username> [--post <post_id>]...` reassigns the visible author of a topic's OP (or specific replies) via `POST /t/{id}/change-owner.json`, validating the target username and honouring `--dry-run`. Phase 2 implemented: `dsc post change-owner` resolves the post's topic and delegates to `topic change-owner` scoped to that post. Remaining: Phase 3's bulk file-driven mode - demand-driven; no live driver has asked for it since Phase 2 shipped. Driver: content compiled from a staff member's source document, posted under the operator's admin account, then reassignment to the actual author (ACCM Discourse). Spec: [topic-post-ownership](commands/topic-post-ownership.md).
- [ ] **R51 - Ownership reassignment beyond topics and posts** - confirmed gaps as of 2026-08-26: `dsc group` has no owner surface (group owners are a first-class Discourse concept distinct from membership) and `dsc invite` has no notion of the invite's `invited_by` creator. Others to survey: saved Data Explorer queries (`created_by`), uploads (`user_id`), personal-message participants, badges, reviewable claims. Phase 1 is **discovery, not implementation**: establish per entity whether the admin API exposes reassignment, capture exact requests and redacted responses, and record which are reassignable versus immutable audit fields. Open design question: entity-native verbs (`dsc group owner add/remove`) versus a repeated `change-owner` verb; group ownership is a set, so consistency with `dsc topic change-owner` should not be assumed. **Candidate for closure if no operator need materialises.** Driver: the same need that produced R49, generalised. Related: [topic-post-ownership](commands/topic-post-ownership.md).

### New command surfaces

- [x] **R53 - `dsc file audit|push|pull`** - complete (all phases implemented on `main`, v0.17.0/v0.18.0): checksum-verified regular-file transfer over configured SSH hosts. `file audit` compares local vs remote SHA-256/size per forum without transferring contents; `file push` stages via same-directory `mktemp`, verifies the checksum in-script before any mutation, atomically renames, refuses symlink destinations, takes a timestamped backup of existing destinations by default (`--no-backup` opts out), supports explicit `--sudo`, idempotent checksum no-op, full dry-run plans including the effective host-key checking mode, fleet `all`/`--tags` via the R48 selector with `--yes` required and bounded `-p`/`-m` parallelism; `file pull` streams through a single-invocation fetch script (checksum on stderr, bytes on stdout), refuses symlink/non-regular remote sources, writes atomic locals, and fleet pulls emit flat `<discourse>--<remote-basename>` files with pre-validated destinations. Verified end-to-end against the fake-ssh fixture. **Real-driver verification completed 2026-09-04** against three internal non-critical hosts (bawmedical, discourse.koloki.co, koloki-demo): the fixed fallback updater (SHA-256 `bc029073...`, which adds `--all --force --filter until=` to the image prunes) was pushed via `dsc file push` with `--owner root --group root --mode 0755 --sudo`, all three post-push audits report matching checksums, and each host's `update.sh --check` passes (disk healthy, no reboot pending). The pilot also caught and fixed a real bug: the default timestamped backup was silently skipped on every push (`remote_file_checksum` reports a present destination as `present`, but the existing-destination check only accepted `different`/`same` from an earlier iteration); verified live on the pilot host and pinned with a regression test (`0a7afec`). Driver: the canonical fallback update script needed controlled deployment to 16 managed hosts twice. Deliberately excludes arbitrary remote execution and recursive sync. Spec: [file-transfer](commands/file-transfer.md).
- [ ] **R58 - `dsc board list|show|pull|push`** - drive the official Discourse Boards feature (core plugin, September 2026, Business/Enterprise) through its `/boards/api/*` plugin API. Phase 1 read-only: list, show, and snapshot boards to stable YAML/JSON (pull includes floater cards, not just topic cards - decided 2026-09-03, a snapshot omitting floaters would misrepresent the board) so Marcus's local-first Markdown Kanban tooling can view a Discourse roadmap as ordinary files with Discourse as write-master. Phase 2 guarded writes: declarative board/column/floater-card push with complete dry-run plans, topic cards by explicit `topic_id` only, and guarded `--prune` (board deletion cascades everything). Discovery complete 2026-09-03 against bawmedical (Discourse 2026.9.0): full endpoint/serializer shapes captured in the spec, including quirks (relative `after_card_id` ordering, whole-object column updates, bare-hex colors, `to_column_id` vs `column_id`, `direction` for column moves, silent tag-binding ignore on partial payloads, upstream `constraint-preview` 500). Driver: the Boards API is undocumented in the official API docs; without capture the shape would have to be re-derived. Deliberately excludes mutating topics as a board side effect. Spec: [boards](commands/boards.md).
- [ ] **R59 - `dsc upcoming-change` and `dsc setting upload`** - expose Discourse's supported Upcoming Changes API through list/show and explicit idempotent enable/disable commands, then add a validated upload-and-bind workflow for upload-type site settings. Driver: Discourse's September 2026 generated `/llms.txt` is a hidden Upcoming Change, and safely replacing a third-party generator requires binding reviewed files without raw API or Rails-console workarounds.
